# 通用自检清单（任何项目交付前跑一遍）

逐条核查，每条回答：✅ 符合 / ❌ 不符合 / ➖ 不适用，并给出依据（文件或代码位置）和不符合时的风险。只诊断，先不要改。最后按“先安全（含 AI 功能、供应链、Agent 操作）→ 再稳定性 → 最后结构规范”排序，标出最该先修的 3 项。

> 标 ⭐ 的 8 条是**最小必查**：时间再紧也要跑完，它们对应"出事就不可逆"的风险。
> 项目里只要接了大模型 API，第 11–13 条按同等必查对待——它们对不接 AI 的项目才可记 ➖。

> 每条必须给出**证据位置**（文件路径 + 行号或函数名）。给不出证据的一律记 ❌ 而不是 ✅——“看起来没问题”不算通过。

## 【安全与资金】

1. 前端是否未直接访问数据库（用 BaaS 时是否已正确配置行级权限）？
2. 关键权限判断是否在后端独立做（不只前端）？
3. ⭐ 密码是否用 bcrypt/argon2/scrypt + 随机盐存储（非明文、非 MD5/SHA 自拼）？
4. ⭐ 金额字段是否用整数最小单位或精确十进制（非 FLOAT/DOUBLE/REAL）？
5. ⭐ 身份证/证件等是否加密存储 + 展示脱敏？支付卡信息是否交给持牌机构而非自存？
6. 不可删数据（订单/付款/合同/财务）是否软删除 + 审计？
7. ⭐ 敏感配置（密码/API Key/密钥）是否未提交进 Git、未放进前端变量？
8. 默认账号是否强制改密、未在公开文档明文写死？
9. ⭐ SQL 是否全部参数化（无字符串拼接）？
10. ⭐ 关键接口是否按 user_id/租户过滤，防越权？登录等接口是否有限流？
11. 模型输出是否经过校验/转义后才展示、入库或执行（未直接 eval、未直接拼进 SQL/命令）？
12. 用户提交的内容是否与系统提示分开传递（未直接拼接）？
13. 模型 API Key 是否只在后端调用、未出现在前端包里？是否设了单用户与全站调用上限？

## 【稳定性（防“一改就崩”）】

14. ⭐ 是否有 Git 且能一键回退？真实数据是否有单独备份？
15. 是否有“红绿灯”（至少一条冒烟检查，核心功能有基础测试）？
    新加的每一条校验或拦截规则，是否本身也有一条测试覆盖？
16. 数据库建表脚本与代码引用字段是否完全一致（无靠静默 ALTER 维持的隐性不一致）？
17. 是否无“捕获异常后既不处理也不记录”的静默吞错？
18. 数据库结构是否有正规迁移文件作为唯一来源？

## 【结构与规范】

19. 目录、模块边界是否清晰？
20. 是否有设计 Token，样式是否未硬编码？
21. 同类 UI 是否已抽象复用（无大量复制粘贴）？
22. 文案是否统一管理（为多语言预留）？

## 【供应链与 Agent 安全】

23. 依赖是否锁定版本且 lockfile 已提交？是否无来路不明或名称近似仿冒的包？
24. ⭐ Agent／自动化是否被禁止无人值守执行删除、强推、部署、改线上配置？
25. 密钥是否从未粘贴进 AI 对话、issue、日志？启用的 MCP／插件来源是否可信？
